# CNA pre-join QoS protocol CNQ v1

Owner approved 2026-11-06 (GAP-17). Additive service capability `qos-prejoin-v1`. Existing control `v:1`, CNR relay
v1 codec/hello, `sessions.find` result and persistent database schema stay as-is.
The server implements the control operations and endpoint together. This protocol
extension does not authorize deployment.

## Control and credentials

All requests retain the existing strict `{v,id,op,game,token,args}` HTTPS envelope
and limits, title binding, authentication and safe errors. Exact new args/results:

* `sessions.findQos {kind,localCount,properties,start,limit}`: same validation,
  redaction and search predicates as find, limit1..32. Result
  `{start,more,sessions:[{listing:<existing advertisement>,permit:<64 lowerhex>,
  lifetimeMs:30000}]}`. Search count/lookahead/pagination is unaffected. Mint only
  for rows actually returned. A valid no-match response contains no permits.
* `sessions.qosTicket {permit}`: consume one actor/title/family-bound listing
  permit once; result `{ticket:<64 lowerhex>,probe:<32 lowerhex>,lifetimeMs:5000}`.
  Ticket is only for the searcher role. No session/machine override accepted.
* `sessions.qosHostTicket {session,participants:[access,...]}`: same complete
  machine group authentication as relayTicket, with current host-only ownership
  and live game relay grant required. Result `{ticket:<64 lowerhex>,lifetimeMs:5000}`.
  This creates responder-only authority; it is not a machine-routing credential.

32-byte random permits/tickets generated by existing cryptographic RNG, keyed by
SHA-256 only in bounded process memory; no secret persisted, logged or echoed in
errors. A probe id is random nonzero16 bytes, never an account/machine/session id.
Records retain game, actor, revocable refresh family, session, current host epoch
(machine+host-change generation), original predicate/localCount and deadline.
Access rotation within the same live family is okay; revoked family/new sign-in
family cannot inherit the permit. Existing membership/privilege/lease checks and
block/avoid/public-capacity/join-in-progress predicates are rechecked before
redemption and Open. Searcher must still be a nonmember; joining cancels its jobs.
A host group change invalidates its responder credential; a complete current
group must acquire fresh authority, including every new participant family.
Ordinary settings revision changes do not invalidate a still-matching listing;
host identity/epoch changes always do. No host epoch rolls back on reconnect.

Uniform NOT_AUTHORIZED for unknown/used/foreign/mismatched/expired permits,
invalid token UNAUTHENTICATED, malformed shape INVALID_ARGUMENT; caps return
LIMIT_EXCEEDED, issuance request frequency RATE_LIMITED. These responses contain
no session existence detail. Host membership errors retain existing safe codes.
The ephemeral issuance operations are explicitly non-durable/non-replayed,
charged to ordinary request budgets plus QoS budgets; duplicate request IDs are
refused rather than replaying secrets. Losing a response consumes bounded quota
until expiry and is not automatically retried by the client. Do not add these
operations to the durable mutation replay-result cache.

State is in memory under a bounded QosAuthority owner with steady-clock injection
for tests. Each authenticated account has128 probe control attempts per rolling60s
(including invalid attempts), independent of other accounts. Exact limits: 32 outstanding permits/actor, 1024/title, 8192/process;
8 findQos calls/account per rolling60s (prune elapsed entries before admission),
4 active jobs/account, 4/current host, 64/title, 128/process. Host responder
connections max1/session and256/process; searcher connections count as jobs.
Admission is atomic across counters; failure allocates nothing/consumes no permit.
Successful qosTicket atomically reserves one job; unused connection ticket expiry
releases the reservation. A failed auth/reconnect never replaces a live responder.
Cancel/disconnect/expiry immediately releases live counters; used-permit tombstones
expire at the original30s deadline. TTL pruning runs on requests and timer, so idle
sockets cannot retain expired resources. Shutdown/restart discards all authority.
No quotas are refunded by pretending a canceled permit was never used.

## WebSocket channel

Verified TLS WSS on the configured control service authority (derived URL, never a
server-supplied host URL), exact target `/cna/qos/v1`, no query/compression. Existing
explicit numeric-loopback insecure policy applies. Bounded UTF-8 text hello <=1024
bytes within5s, exact `{v:1,id:<identifier>,game:<identifier>,ticket:<64lowerhex>}`;
role comes solely from redeemed ticket. Welcome exactly
`{v:1,id,error:"OK",result:{role:"searcher"|"host",probe:<id-or-null>,
maxFrameBytes:1200,maxQueuedFrames:16}}`. No peer machine id, IP, membership,
roster, game payload, endpoint or credentials in a probe frame. Host role gets
null probe in welcome and receives per-job Begin frames.

Single binary application frame per complete WS message, <=1200 bytes. Bound
fragment accumulation **before** growth. Unknown text after hello fails. Safe
close codes follow relay-v1: malformed1002, policy1008, invalidUTF8 1007,
oversize1009, empty reasons; ping/pong/close controls count toward ingress budget.
Transport ping/pong is never a QoS measurement or a valid host echo.

| Offset | Size | Meaning |
|---|---:|---|
|0|3|ASCII CNQ (43 4e 51)|
|3|1|Version1|
|4|1|Type below|
|5|1|Sequence|
|6|1|Count|
|7|1|Reserved zero|
|8|16|Nonzero service-issued opaque probe id|
|24|8|Unsigned nonce, network byte order|
|32|variable|Type payload, exact length|

All numeric body fields are unsigned big endian. Types and exact schema:

| Type | Bytes | Seq/count/nonce | Direction and payload |
|---|---:|---|---|
|1 Ping|32|seq0..3,count4,nonce!=0|searcher→host, relay forwards only|
|2 Pong|32|seq0..3,count4,nonce!=0|host→searcher, same outstanding Ping tuple only|
|3 Up|1200|seq0..7,count8,nonce0|searcher→host,1168 zero padding bytes|
|4 Down|1200|seq0..7,count8,nonce0|host→searcher,1168 zero padding bytes|
|5 Report|48|seq0,count8,nonce0|host→searcher: u32 acceptedCount0..8 at32, u64 elapsedUs at36, u32 reserved0 at44|
|6 Cancel|32|seq0,count0,nonce0|either peer→service; service cancels only this job, not game relay|
|7 Begin|32|seq0,count0,nonce0|service→host only; activates one bound probe|

Report: count<2 must have span0; count>=2 needs 1..3,000,000us. For publication
count>=4 is required. Zero padding/reserved fields are validated, never echoed
as arbitrary bytes. No arbitrary payload echo; Ping reflects only header nonce.
A service-side outstanding nonce mask rejects duplicate/unsolicited Pong tuples.
Each train sequence can be forwarded once; duplicate/reordered receipts cannot
increase receiver's accepted count. Do not regenerate/report upstream at relay.
Host's timing report is untrusted input bounded by schema; an authenticated
malicious host can still lie about its network. This is telemetry, not anti-cheat.

Parser precedence: <32 QOS_TRUNCATED; >1200 QOS_TOO_LARGE; magic QOS_MAGIC;
version QOS_VERSION; type QOS_TYPE; reserved QOS_RESERVED; all-zeroid QOS_PROBE;
then exact type length QOS_LENGTH; sequence/count/nonce/payload QOS_FIELDS.
No payload allocation before full schema validation. Decoder returns a borrowed
view; frame ownership is retained across async writes.

Golden Ping literal: `434e5101010004000102030405060708090a0b0c0d0e0f10000000000000002a`
(32 bytes; probe bytes1..16, seq0,count4,nonce42). Pong changes byte4 to02.
Up golden uses `434e5101030008000102030405060708090a0b0c0d0e0f100000000000000000`
followed by exactly1168 zero bytes. Report count8/span70000 body is
`00000008000000000001117000000000`.

## Probe execution and timing

Searcher welcome followed by Begin to the exact bound host. Only live host
responder attached to current validated member game relay may receive it.
Start measurement after welcome (connect time excluded). Send4 unique nonce
Pings spaced100ms; send train of8 Up frames (no artificial interframe pacing,
serialized nonblocking writes). On Begin the host sends8 Down frames and echoes
valid Pings immediately in its worker. It records Up arrival steady timestamps
when complete frames are decoded, not send times/service times/frame updates.
Send one Report after all8 accepted Up frames, or at1000ms from Begin for partial
loss. Searcher waits for >=3 unique valid Pongs, >=4 Down frames and valid Report
count>=4; finish only after Report and the four-ping observation period (last
Ping's300ms send plus its bounded remaining wait, or all4 Pongs). At3s from
welcome, finalize available if thresholds met, otherwise unavailable; client
whole-job5s/search30s ceilings can terminate earlier. Prefer completion as soon
as all4 Pongs,8 Down and Report arrive. Missing one Pong/Down waits until3s.

Rates: `(acceptedCount-1)*1200*1000000/elapsedUs`, integer floor and INT_MAX clamp.
Only in-order strictly increasing train sequences count. RTT is local steady
receive minus actual local complete-Ping send time, unique nonce matching.
Average/minimum use accepted samples; average rounded to nearest wholems after
mean, ties upward; minimum also rounded nearest wholems. No clock sync needed.
Discard bogus negative/unsent/old tuples; do not subtract clocks of different peers.
Server forwards reports unchanged only from bound current host; searcher computes
upstream from count/span. Downstream is calculated from local Down receipt times.

A job deadline uses `now>=deadline`; later Pong/Report cannot revive it.
The service reserves at most5s from searcher ticket issuance (including redemption,
welcome/setup); redemption cannot restart that clock. After its first Ping,
forwarding expires at3s or that earlier5s deadline. This leaves welcome scheduling outside the client's3s measurement
window while preserving the5s whole-job ceiling. Host per-probe state expires
at3s after Begin. Published snapshots have no TTL invalidation. Collection
Dispose/last lifetime cancel sends best-effort Cancel without waiting. No blocking
cancel network call. Host/service release timers independently if Cancel is lost.
New Find/new host epoch/new generation never consumes old probe results.

Ingress: <=32 frames including controls and <=20480 binary bytes/role/job for its
entire3s life. Ping/Pong4, Up/Down8, Report1 are exact per-type caps; Begin is
service-only. One whole-job aggregate token budget, not a fresh rate window for
each frame. Queues <=16 frames/19200 bytes/connection including active write;
slow receiver drops/cancels its probe without growing the executor queue. Host
has4-job cap but the connection queue remains16 total. No probe flooding of the
session game queue. Add per-address handshake admission under existing listener
control cap and separate authenticated QoS cap. Process/title limits enforced
before executor posts/buffer copies. Bytes and counters are not public QoS rates.

## Compatibility matrix

New CNA + old service: no capability => normal find, pending false forever.
Old CNA + new service: old operations/hello/relay unchanged; host has no responder
=> new searcher measurement expires false. New+new host/searcher => real probes.
Transport-disabled/browser builds retain NOT_SUPPORTED internally and false QoS;
no native worker can be constructed there. Restart discards permits/active jobs;
ordinary session relay recovery behavior is preserved. Schema version unchanged.

## Implementations and qualification

Canonical codec: `protocol/include/CnaService/QosProtocol.hpp` and
`src/QosProtocol.cpp`, copied byte-identically to CNA's internal protocol layer.
Golden byte corpus: `protocol/golden/qos-v1.json`; unit assertions use independently
written literals, not runtime-generated expected values. Authority is in
`src/QosAuthority.cpp`, role routing in `src/QosHub.cpp`, bounded write accounting
in `src/QosFlow.cpp`, and TLS endpoint in `src/QosListener.cpp`.

`service_qos_authority`, `service_qos_protocol`, `service_qos_routing` test bounded
logical behavior. `service_cna_qos` uses two actual CNA processes before public
BeginJoin for PlayerMatch and Ranked; `service_cna_qos_nohost` disables only the
test host's probe component and verifies that healthy control/game traffic cannot
produce QoS. `service_cna_qos_nat` requires the existing rootless NAT prerequisites
and skips77 when unavailable. No public-Internet capacity or anti-cheat claim.

2026-11-06 qualification boundary: deterministic client and service fixtures pass.
The current build sandbox denies TCP/UDP loopback bind with EPERM; real paired
process qualification has not passed here. NAT prerequisites are unavailable
